# Workspace catalog developer binaries

`catalog_gen` and `image_catalog_gen` are explicit `pi-ai` targets gated by the
empty, default-off `dev-catalog-tools` feature. They add no dependency or runtime
library path. Build with `cargo build -p pi-ai --features dev-catalog-tools --bins`.
Run from the workspace root, using `--help`, no arguments/`--check`, or
`--output PATH`. Help works independently of the workspace assets.

These are workspace-local executables, not standalone installed normalizers.
They require `/usr/bin/python3` (3.11+), checked-in Python/Node drivers and captured
assets, the pinned Node executable/ICU/locale, and locally available upstream Git
objects configured by `upstream-map.toml`. The subprocess receives exact argument
values with a cleared environment and `/usr/bin:/bin` PATH; the accepted Node
runner retains its existing sanitized environment. No live feed is recaptured.

Every successful check or export executes the accepted complete offline pinned
text and image generator workflow, then compares all regenerated bytes/provenance
against canonical output. Accepted generator/input/output files are unchanged.
Source, capture, runtime or canonical-output failures return nonzero and never
create the requested output. Unknown arguments also fail. Export writes and
closes a private temporary file in the destination filesystem,
then atomically publishes it with a non-replacing hard link. Existing files or
symlinks, including a racing creator, are untouched. Failure cleanup only owns
the private temporary directory; it never unlinks the final output pathname.
Ordinary write/flush/publication failures leave no partial final artifact. Parent
directories must already exist and support hard links; there is no overwriting
fallback. This is not a crash-durable publication protocol: termination can leave
private temporary storage, and no power-loss persistence guarantee is made.

The deterministic artifact is `{schemaVersion:1,family,provenance,catalogs}`.
`family` is `text` or `images`; `provenance` is the complete accepted regenerated
provenance object. `catalogs` is an array of `{provider,models}` objects. Text
provider order is **openai, google, anthropic, deepseek, openai-codex, openrouter**;
images contains only **openrouter**. Each `models` array preserves its accepted
source order and its exact JSON bytes, independently of provider array order.
Text exports450 models; images exports52 captured models. Excluded products and
historical50 image values are not exported as family models; full provenance
retains their source-evidence distinctions. This is parity for the dated input
capture, not historical text catalog values.

Actual built-binary tests cover help/default/check, exact502 model values and
provenance, deterministic family outputs, spaces in paths, existing-file refusal,
unknown arguments, missing workspace, and fixture-only capture/source/canonical
corruption. Python controls additionally prove exact source-array bytes and
symlink refusal, the previously failing cleanup interleaving, private write/flush
failures, publication failure and a competing final creator at publication. The
canonical gate includes both suites.
