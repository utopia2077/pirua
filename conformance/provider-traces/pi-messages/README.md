# pi-messages trace authority

`trace.json` is source-derived from pi-mono `853a80d26c90a14c1886f0ebb8ffaae133ca2185`, `packages/ai/src/api/pi-messages.ts` and its offline `test/pi-messages.test.ts`. Synthetic time is fixed at 7. The source test text/tool sequence is extended with source-defined signatures, thinking, rewrite metadata and Unicode byte splits. Expected content snapshots are recorded independently of Rust reducer output; the test combines each with the fixed source identity, pending reason and zero usage to compare every complete event.

Rust event projection keeps start IDs and end signatures inside their typed partial content, omitting duplicate JS-only root properties. Owned snapshots capture each event's observable state rather than retaining mutable JS aliases. Provider error bodies/messages/codes/URLs are classified transiently and omitted from public diagnostic rendering. Safe phrases preserve both retry and context-overflow booleans; HTTP status remains in the diagnostic. Server aborted events preserve their content and usage but use fixed cancellation text. Missing/empty error messages acquire a fixed valid terminal message.

Cost zero values are written as `0.0` to compare the accepted finite-f64 Rust cost projection; JavaScript's `0` and `0.0` have identical numeric meaning. Request headers preserve exact-key object-spread replacement, then Fetch-compatible case-insensitive joining and value whitespace trimming. An offline Node Headers probe confirmed that an uppercase `ACCEPT` override joins with the lowercase default, while lowercase `accept` replaces it. Null is removed before either operation.

Closed event decoding rejects duplicate/unknown fields, null optional fields, unsafe counts and sparse/wrong-kind content indexes. These checked Rust boundaries are explicit normalization of unchecked JS event casts, not evidence that upstream validates them. Host-configured stream/frame/content/tool-input/error-body bounds reject excess data rather than truncating it. A valid terminal stops frame parsing before an irrelevant hostile tail. pi-messages timeout/retry options remain intentionally ignored.

`error-classification.json` records 14 independently verified statusText/body/code combinations. Exact pinned upstream classifiers executed offline in Node matched every expected pair. The adapter consumes the actual transient HTTP reason phrase before redaction: HTTP/1 `429 Too Many Requests` suppresses context overflow, while the same status/body with HTTP/2's empty phrase does not. Custom phrases, empty messages, code exclusions and BOM handling remain distinct. Suppressing status text causally fails this matrix.

The production-backend test captures actual POST bytes and split chunked SSE, verifies both normal completion and cancellation release, and asserts that a Latin-1 `é` header reaches the peer as byte `e9`, never UTF-8 `c3a9`. The provider separately rejects header values outside the Fetch ByteString range. Only local loopback endpoints are used.

`status-text-decoding.json` records ten actual local Node v26.8.1 Fetch results from literal HTTP/1 reason-phrase bytes, with expected control classifications from executed pinned upstream helpers. The transport field is a Latin-1 projection of bytes, not predecoded text. The adapter rejects raw scalars above 255, recovers the bytes, then performs UTF-8 replacement decoding. Leading, internal and repeated BOMs are preserved in statusText; this differs from the separately tested Response.text BOM stripping. Unit tests compare exact decoded strings, and scripted transport tests compare the final redacted classifications. Native lossless reason capture is a separate dependency; these synthetic raw-port tests do not claim its byte-capture acceptance.

`wire-numbers.json` records 28 raw number spellings executed through the exact pinned converter in Node v26.8.1. It distinguishes the converter's unchecked retention from the Rust target's finite safe signed/unsigned admission rule. Decimal/exponent spellings and negative zero are projected by numeric value only for nine event indexes, seven usage counts and three rewrite counts. Raw-SSE tests cover all 812 field/terminal/spelling combinations, including signed range endpoints and rejection of fractional, unsafe and nonfinite values. Safe but oversized indexes still fail the independent reducer resource limit. Non-number values, missing required fields, duplicate/unknown fields and explicit optional null remain rejected. Cost values and arbitrary tool arguments are not normalized, and core durable integer/Usage Serde remains unchanged.
