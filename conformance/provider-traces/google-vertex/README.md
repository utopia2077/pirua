# Canonical Google Vertex

This default-off `wire-google-vertex` family has its own typed
`GoogleVertexOptions`, `GoogleVertexApi`, independent generated-ID owner and
Vertex client configuration. It reuses the existing private Google SDK converter,
decoder and stream reducer, not GenAI's Express-only routing or thinking policy.
GenAI's original public paths are reexports of the extracted exact engine; its
149 request/211 read/31 metadata fixtures and assertions are unchanged.

## Evidence and reproduction

Authority is full pinned `api/google-vertex.ts` and lazy entry at
`853a80d26c90a14c1886f0ebb8ffaae133ca2185`, with actual installed Google SDK 1.52.0
index.mjs SHA256
`748f86443c1c2c80e4ecf568d0c033ad9f1e9f34926c810e35c77e965a951c33`, Node 26.8.1.
The metadata oracle additionally pins bundled Undici 8.10.0 and its exact hash.
Expected values are executed source observations, never generated by Rust.


The 169 complete adapter cases retain logical payload, actual SDK HTTP request,
all event snapshots, hook order, auth configuration/URL/header consumption,
retry delays and final classifications. They include raw/simple options,
Gemini/Gemma differences, key trimming/marker/placeholders, scoped/ambient env
precedence, regional/global/collection/Express routes, SDK model/schema/config
conversion, header alias/null rules, usage/signature/tools/finish/error/retry
behavior and credentials with Other/present-undefined/401/503 failures.

The 211 read arrangements and 31 metadata cases execute Vertex's complete source
with the actual SDK, including byte splits, UTF-8 state, per-read JSON errors,
delimiters, incomplete EOF and private full ByteString metadata-error templates.
The separate two-case auth oracle uses real Node Fetch plus a controlled delayed
credential leaf to prove SDK timeout and caller signal do not themselves settle
pending auth; eventual Fetch sees an aborted signal and opens no connection.
All credentials, files and hosts in fixtures are synthetic. GoogleAuth getClient
is replaced by a forbidden-discovery guard and getRequestHeaders by the explicit
test leaf. There is no real file, token, metadata or provider access.

An early Vertex oracle omitted URL from its VM globals; this incorrectly forced
the source fallback API-version regex for a query/fragment base. Adding the real
URL global corrected that new oracle observation; no accepted GenAI expectation
or implementation was changed to match the harness defect.

## Configured credential ownership

The frozen non-Serde boundary is:

```rust
GoogleVertexAuthConfig<'a> { key_filename: Option<&'a str> }
GoogleVertexAuthProvider::create_session(config)
    -> Result<Box<dyn GoogleVertexAuthSession>, ModelsError>
GoogleVertexAuthSession::get_request_headers(endpoint, runtime)
    -> BoxFuture<Result<HttpHeaders, GoogleVertexAuthError>>
```

Both traits are Send+Sync and the async method explicitly shares one lifetime
between self, final RequestEndpoint and original RequestRuntime. The fixed scope
is `https://www.googleapis.com/auth/cloud-platform`; callers cannot substitute a
scope through this config. Config/options/error Debug output is redacted.
`with_auth_provider` supplies a trusted construction capability, not discovery.

One bounded synchronous no-I/O session is created per ADC invocation before
payload; outer retries reuse that session. Every attempt calls its async leaf
after payload conversion and final initial URL construction, even when caller
Authorization is already present. Returned fields fill only absent names;
present empty Authorization suppresses replacement. No auth is reacquired per
Fetch redirect. Ordinary duplicate auth fields join, Cookie uses semicolon
joining, and Set-Cookie fills only its first separate source entry; the later
entry sees the now-present name and is skipped. A complete source request witness
caught and corrected an initial combined Set-Cookie value.
Sessions/futures drop on terminal/error/cancel; no global auth
cache is introduced. Missing configured capability fails before payload with a
typed Auth-category local error, not empty headers or a fallback network path.

API-key resolution happens first: ECMAScript-trimmed real key bypasses the port
and all project/location/file configuration. Empty, exact credentials marker and
whole placeholder select ADC. Explicit project/location precede scoped/ambient
truthy fallback; a scoped empty value does not suppress ambient. These values and
keyFilename are not globally trimmed. SDK explicit project/location clears its
ambient key. Source custom base is trimmed, ignores literal `{location}`, sets
COLLECTION and conditionally suppresses v1. Ambient SDK base does not gain those
pi-only flags. Credential-bearing effective endpoints never mutate public models.

`GoogleVertexAuthError::Other(ModelsError)` differs from
`Provider { status: None/Some, failure: ModelsError }`: status presence controls
the source Google outer retry helper, including present-undefined retryability.
No second generation retry owner is added. Arbitrary external credential exception
prose is normalized to closed safe nonretry/nonoverflow final text; safe status
remains structured and outer retry semantics remain. The future S05 concrete
credential implementation owns token/discovery/refresh policy and any finer
reviewed error projection, not an arbitrary raw-string inlet here.

## Timing, state and limits

Original caller cancellation races a noncooperative leaf and releases it/session
without sending. This is the explicitly accepted Rust normalization relative to
the source's uninterruptible credential await; it does not undo a remote refresh.
An explicit SDK timeout does not preempt that auth wait. After successful auth,
elapsed injected-clock milliseconds are deducted and an expired deadline rejects
before network; otherwise the remaining whole-response budget is forwarded to
the existing transport. Auth rejection keeps its own status/error stage before
timeout observation. Neutral timeout remains ignored and no default timer is
invented. Hosts own a coherent request clock; physical timing precision and clock
adjustments are not a wall-clock-independent scheduling guarantee.

Native tests exercise API-key fragmented wire/cancel, ADC Authorization/quota
headers and partial usage/session cleanup, delayed auth with timeout versus
original caller cancellation, and metadata constructor failures through real
loopback HTTP. Scripted tests prove missing port, typed option/null admission,
counter exhaustion, noncooperative payload/body/leaf cancellation and bounded
resource cleanup. Source-backed custom-fetch mocks are Preconstructed; native
overrides are RawNetwork.

Vertex minimal flash-lite budget is 128, not GenAI's 512. Vertex has no Gemma4
level-special case. Each family has a separate default module-global counter;
injected GoogleToolCallCounter owners remain explicit capabilities. A mutant
sharing the default Vertex owner with GenAI failed the mixed-family test:
GenAI received lookup_7_3 instead of lookup_7_1. Restoring separate owners passed.

Existing SseLimits, 16 MiB cumulative response bound, 4096 content blocks,
262144-byte tool arguments, core JSON/count bounds and safe counter exhaustion
remain unchanged. Private decoder/storage limits are logical, not physical RSS
or zeroization promises. Ordinary V8 JSON parser and arbitrary helper exception
prose retain the approved normalization; actual HTTP/SSE/metadata provider strings
retain full normal/cap classification before redaction. JavaScript prototypes,
executable SDK tools/AFC objects and mutable external SDK singleton configuration
are not portable DTOs. No browser state, ADC discovery or live interoperability
claim is made. No provider/facade factory or S05 work is activated.


## Ordered payload composition

The shared Google engine retains the accepted non-Serde `WirePayload` from
logical construction through middleware and SDK consumption. The original
169-case request, 211-case read, 31-case metadata, and two-case auth fixtures
remain unchanged.

`payload-order.json` preserves the original two-case source counterexample:
replacement headers `x-order=lower` then `X-Order=upper` produce `lower, upper`,
and their reverse produces `upper, lower`. The complete pinned adapter and actual
SDK generate both observations with an explicit synthetic API key, so the ADC
session is skipped. The Rust regression compares the full request, logical
payload, callback/auth/sleep order, every event and final result, then verifies
body release. Before carrier composition, the forward case fails while the
reverse control passes; afterward both pass. Expected data is source-generated.

```sh
env -i PATH=/usr/bin:/bin NODE_NO_WARNINGS=1 node conformance/provider-traces/google-vertex/oracle.mjs --payload-order --check
cargo test -p pi-ai-providers --features wire-google-genai,wire-google-vertex,native --test google_vertex --test google_genai --locked --offline
```
