# Google GenAI source-bound traces

This candidate implements only the canonical `google-generative-ai` family, behind
the default-off `wire-google-genai` feature. It does not register a default
provider or implement the separate Vertex family.

## Authority and reproduction

Both executable oracles load complete upstream modules from Git commit
`853a80d26c90a14c1886f0ebb8ffaae133ca2185` in `upstream/pi-mono`, and execute
the actual installed `@google/genai` 1.52.0 Node SDK. The SDK `dist/node/index.mjs`
SHA-256 is `748f86443c1c2c80e4ecf568d0c033ad9f1e9f34926c810e35c77e965a951c33`.
The captured runtime is Node 26.8.1. No expected response, request, event or
classification is generated by Rust.

```sh
env -i PATH=/usr/bin:/bin node conformance/provider-traces/google-genai/oracle.mjs --check
env -i PATH=/usr/bin:/bin node conformance/provider-traces/google-genai/stream-oracle.mjs --check
env -i PATH=/usr/bin:/bin node conformance/provider-traces/google-genai/metadata-oracle.mjs --check
cargo test -p pi-ai-providers --features wire-google-genai,native --test google_genai --locked --offline
```

`trace.json` retains 149 complete adapter observations: logical payload, SDK wire
request, all event snapshots, terminal result, classification, hooks and retry
delays. `stream.json` retains 211 input-read arrangements and seven deduplicated
complete observations. Three of those cases use a real local TCP server with
non-ASCII HTTP status bytes. Other oracle requests use an injected global Fetch
that cannot contact a provider. Credentials and endpoints are synthetic; child
environments are cleared by the commands above. Source console warnings are
observed, not reproduced as Rust diagnostics.

Primary upstream modules are `api/google-generative-ai.ts`, its lazy entry,
`api/google-shared.ts`, and the complete imported retry/error/transform helpers.
SDK anchors in the hashed file include model conversion at 2943, generated
request conversion at 10304/10326, request and stream processing at 13145–13315,
HTTP failure conversion at 13465, generated streaming calls at 15134/15176, and
constructor/environment selection at 21156–21366. The source's actual file name
is `google-generative-ai.ts`, not `google.ts`.

## Observable stages

The adapter constructs source-level `{model, contents, config}`, runs the trusted
payload hook, and then applies SDK routing, converters and headers. This is not
the HTTP JSON shape: system instructions and tools are root fields, while sampling
and thinking belong in `generationConfig`. Explicit API-key cloud Express mode
is retained when the SDK environment flags select it; enterprise takes precedence
over Vertex even when false or empty. Project/location discovery and ADC are not
performed. This is an SDK routing branch, not activation of the Vertex family.

There is no source `onResponse` call. There is no SDK default retry or timeout,
and the neutral timeout option is ignored as in source. An explicit trusted
payload `config.httpOptions.timeout` applies to acquisition and body consumption.
One outer Google retry owns the complete failed HTTP attempt, including its body;
SDK ApiError does not expose response headers to that retry. Successful streaming
bodies are outside retries. Original caller cancellation retains its identity.

The private SDK decoder probes each decoded reader chunk for a whole JSON API
error before appending it to the framing buffer. Equal concatenated bytes split
into different reads can therefore produce different results. UTF-8 decoding is
incremental, without a final decoder flush. Only trimmed segments starting with
`data:` are yielded; this is not generic SSE field parsing. Unknown finish reasons
set `rawStopReason` and fail before current usage is assigned. A mutation that
substituted `OTHER` for unknown reasons made the complete-event matrix fail on
`finish-server error prompt is too long`, including its preserved earlier usage;
restoring the checked admission made the matrix pass.

Actual provider HTTP/SSE strings are composed before normal and delay-cap
classification, then discarded before safe rendering. Whole-read ApiError JSON
is included. The SDK's conditional `exception parsing stream chunk ...` path is
also reachable: native UTF-8-invalid or non-ByteString HTTP status phrases cause
the constructed chunk Response to reject. The native corpus preserves that
branch's full data interpolation for classification; Latin-1-compatible decoded
`é` is the successful control. The fixed Node WebIDL ByteString TypeError is
not part of the arbitrary parser-prose normalization: its first offending UTF-16
index and code unit are bounded wire-derived observations. The complete fixed
template and data prefix remain private until classification, then are discarded.
`metadata.json` adds 31 actual Node/TCP observations without changing either
original corpus: index 428–430 and 499–504, code units 255/256/428–430/499–504,
high surrogates, multibyte Latin-1 prefixes, billing/quota vetoes and anchored
message contexts. The oracle also captures the actual constructor error so a
private unit test compares the full template, not just its final classifier flags.
A Unicode-scalar mutant failed on 129451 versus the source high surrogate 55358;
restoring UTF-16 iteration passes. Both scripted and native Rust adapters run the
new corpus; original index 429/500 independent review probes also pass unchanged.
Ordinary `chunk.json()` V8 SyntaxError details
remain a separate approved typed-parser normalization: nonretry/nonoverflow,
with the original effect stage and representable partial state. Bad JSON is not
scanned to guess V8's diagnostic excerpt. Arbitrary external helper/callback
exception prose is likewise unavailable through the typed redacted ports; this
exception does not erase provider-authored HTTP/SSE classification.

## State, limits and finite boundaries

Default adapter instances share one module-global atomic tool counter. Only a
missing or repeated tool ID consumes it, and the timestamp comes from the request
clock. `GoogleToolCallCounter::new(SafeUnsigned)` plus the non-Serde construction
setter `with_tool_call_counter(Arc<...>)` provides explicit deterministic test or
host ownership. Fixtures inject zero; a separate two-instance test proves the
default shared owner and that supplied IDs do not consume it. The counter rejects
before exceeding the JS safe integer range, rather than wrapping or resetting.

The existing SseLimits bound incoming bytes plus retained decoded text and pending
UTF-8 bytes, individual decoded segments, and data frames yielded per input read.
UTF-8 pending state is at most three bytes. Temporary input and conversion buffers
are independently bounded by the configured buffer limit; these are logical
bounds, not an exact physical-RSS or secure-erasure claim. Decoder failure clears
owned buffers. Provider defaults independently bound accumulated response bytes to
16 MiB, content blocks to 4096, and each tool argument representation to 262144
bytes. Core JSON depth/node/count limits remain in force. These accumulated
message limits are not confused with pending stream-buffer limits. Counts use
mathematical JS Number projection before safe integer admission.

The finite request boundary is typed options plus JSON-compatible trusted payload
replacement; JavaScript prototypes, executable SDK tools/AFC callbacks, arbitrary
non-JSON objects, custom per-request Fetch functions and arbitrary thrown text
are not portable DTOs. Existing typed Google message/schema transformations are
reused without weakening their contracts. SDK runtime identity is normalized to
`pi-ai-rust`, while protocol-required headers remain covered.

This base predates the independently reviewed shared Fetch content implementation.
The scripted clients observe SDK/custom-Fetch arguments and constructed responses,
not network defaults; future assembly must mark those clients Preconstructed.
Native tests observe actual network behavior and must remain RawNetwork. No claim
is made here to implement global Fetch decompression, browser state or ADC.
Native loopback tests cover fragmented HTTP, explicit timeout, caller cancellation,
partial usage retention, status-metadata errors and connection release. Scripted
noncooperative bodies/hooks and limits verify one body close/drop and no retry
before failed-body completion. No live provider or TLS trust-store mutation is
used by this family unit.
